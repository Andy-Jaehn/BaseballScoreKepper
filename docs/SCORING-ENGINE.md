# 计分引擎与事件回放算法

## 核心模型

计分引擎采用确定性的事件回放模型。新比赛从 `initial` 状态开始；每个正式事件按时间顺序交给 `apply` 处理。事件可以是投球、界内击球、特殊情况、裁判判罚、换人或半局切换。回放完成后得到当前比赛状态。

```
初始状态 + 事件 1 + 事件 2 + ... + 事件 n = 当前比赛状态
```

状态中包含攻守方、局数、球数、出局、垒包、打序、场上阵容、比分、日志和每位球员的原始统计。所有页面、导出和年度汇总都使用这套回放结果。

## 投球与打席处理

- B 增加坏球；累计四坏球时，软件按受迫顺序推进一垒、二垒、三垒和打者。
- S、Foul 和 Fair 计入实际投球；Foul 在两好球后不再增加好球数。
- HBP、IBB 和裁判保送结束打席但不计为普通投球。IBB 同时记入打者 IBB、投手 IBBA 和保送相关统计；满垒时应用按指定规则禁止 IBB。
- 三好球时形成三振。棒球不死三振只在两好球时可录入，并要求记录打者或跑者的结果。
- 待确认的终结投球只放在 `pendingPitch`，确认后才成为正式事件；取消则丢弃暂存事件。

## Fair 的跑垒算法

Fair 流程先记录落点、击球类型、处理野手和处理结果，再按“前位跑者优先”的顺序处理三垒、二垒、一垒和打者。每位跑者的动作可为正常推进、因失误额外推进、封杀、触杀或半局结束。

算法维护一个允许到达垒位的上限：先处理的前位跑者占用垒位后，后位跑者的上限随之降低。因此跑者不能重叠，也不能超越前位跑者。正常推进和失误额外推进分开保存；例如正常推进 2 垒、失误额外推进 1 垒，最终到三垒，但打击仍按二垒安打计算。

在此基础上，软件从已录入事实派生安打、野手选择、失误、牺牲飞球、牺牲触击、双杀、三杀和 RBI。内野高飞不是由落点猜测，而是记录者在野手处理时明确选择；第三出局的得分是否成立，则按封杀规则和已录入的得分与触杀先后判断。

## 特殊情况

特殊情况同样写成事件而非直接修改统计。暴投记投手 WP，捕逸记捕手 PB；牵制每次记投手 PICK，并可附带触杀或失误；盗垒成功记 SB，盗垒失败记 CS，多位跑者同时尝试时记 DS。牵制和盗垒在无跑者时不能开始。

捕手妨碍打击记打者 CI 与捕手 F_CI；不死三振记打者 D3K；投手犯规作为 BK 记录。牵制触杀和其他出局均调用同一出局记账逻辑，因此会同时增加投手 OUT、完成刺杀野手 PO，必要时再增加助杀 A。

## 换人与责任投手

垒上跑者保留其上垒时的责任投手 ID。守备换人替换场上位置；代跑会接替垒位和责任投手信息；守备位置交换不会新建球员记录。这样，之后的得分仍能正确归入原责任投手的 RA 与 ER 计算轨道。

## 自责分影子局

ER 不是在单一事件发生时直接写死，而是在回放后由独立的影子局重建。算法对每个半局、每位责任投手维护一条不含失误的垒包与出局轨道：

1. 实际比赛照常记录比分和跑者。
2. 影子局忽略失误导致的上垒和额外推进；界外漏接可补记本应发生的出局。
3. 后续安打、保送、封杀和触杀按已记录的正常推进重新作用于影子跑者。
4. 只有真实已经得分、且同一跑者 token 在影子局也能得分时，才把该分计为 ER。

这能处理“先因失误得分、后续合法推进足以使其得分”的追溯 ER，以及失误本应成为第三出局、继承跑者、换投后的责任分配等情况。完整的原因码和审计字段见 [earned-runs.md](earned-runs.md)。
