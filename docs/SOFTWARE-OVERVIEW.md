# 软件概览与运行方式

## 软件是什么

钻石记分是一款离线运行的棒球与慢投垒球逐球记分软件。它不是只保存最终比分的表格，而是保存从开赛到结束的比赛事件，再从事件重放出当时的比分、垒包、球数、球员统计和逐打席记录。

软件支持两种比赛类型：

- 棒球从 0 坏球、0 好球开始；两好球后的普通界外球不再增加好球数。
- 慢投垒球从 1 坏球、1 好球开始；两好球后的普通界外球同样不再增加好球数。慢投模式禁用 HBP、暴投、捕逸、牵制、不死三振、捕手妨碍打击和盗垒等不适用入口。

比赛数据保存在本机。每次完成或暂存一次操作都会写入本地存储；重新打开应用时，未结束的比赛可以继续。结束后的比赛可以按年份查看、导出 Excel，或导出 JSON 备份后导入。

## 一场比赛如何运行

1. 在球员页维护姓名、背号和惯用手；姓名以规范化名称保持唯一。
2. 选择棒球或慢投垒球，组建客队与主队，调整棒次和守备位置，并指定记录者、裁判。
3. 比赛中录入 B、S、Foul 或 Fair。完成打席的结果先进入待确认状态，确认后才写入正式事件；取消会恢复此前状态。
4. Fair 和特殊情况会继续要求记录守备处理、跑者推进、出局、失误或得分等事实。软件据此计算安打、出局、得分和个人统计。
5. 每半局三出局后，由记录者显式开启下一半局或结束比赛。软件不会根据领先分差自动判定比赛结束。

## 三层运行结构

| 层次 | 作用 | 主要结果 |
| --- | --- | --- |
| 事件层 | 保存投球、击球、换人、半局切换、特殊情况和裁判判罚 | 可编辑的比赛事实序列 |
| 回放层 | 从开局状态顺序应用事件 | 比分、B S O、垒包、打序、日志和原始统计 |
| 展示与导出层 | 把原始统计转换为比率并组织成页面或工作表 | 比赛数据、年度累计、Excel、JSON |

这种结构的关键是“事件优先”。例如，某次二垒安打后因失误上三垒，事件同时保存正常进垒 2 垒和失误额外进垒 1 垒；页面显示和导出都由同一条事实重放得到，而不是分别维护多套统计数字。

## 状态与保存

比赛状态包括局数、攻守方、B S O、垒包、打序、场上阵容、换人记录、事件日志、未确认投球和 Fair 草稿。运行时的界面状态不是统计的唯一来源：正式事件才是可重建的依据。

因此，取消未确认投球不会留下统计；撤销仅允许在同一未结束打席内删除 B、S 或 Foul，不能跨越已完成打席。删除一场已结束比赛后，年度累计统计会重新汇总，不会保留这场比赛的贡献。

## 文件与离线边界

- Excel 导出包含总览及双方的打击、守备、投球工作表。
- JSON 备份只导出已结束比赛及其所需球员；导入时按开始与结束时间组合识别重复比赛。
- 导入数据先校验比赛结构、阵容、事件类型和统计可计算性，再一次性写入本地数据。
- 软件的统计结论以录入的比赛事实为基础；复杂判罚或无法从事实唯一推导的官方记分判断，仍应由记录者决定。
