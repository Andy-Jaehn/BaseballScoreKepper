# 统计计算与数据管理

## 原始统计与派生指标

引擎先记录可直接归属的原始计数，例如 AB、H、TB、RBI、BB、HBP、SO、SB、CS、WP、PB、PICK、PO、A、E、OUT、RA 和 ER。显示页面和 Excel 在原始计数之上计算比率；分母为 0 时显示 0。

| 指标 | 计算方式 |
| --- | --- |
| AVG | H / AB |
| OBP | (H + BB + HBP) / (AB + BB + HBP + SF) |
| SLG | TB / AB |
| OPS | OBP + SLG |
| FPCT | (PO + A) / (PO + A + E) |
| WHIP | 3 × (HA + BBA) / OUT |
| ERA 棒球 | 27 × ER / OUT |
| ERA 慢投垒球 | 21 × ER / OUT |
| RA9 | 27 × RA / OUT |
| K 9 | 27 × K / OUT |
| IP | `floor(OUT / 3).OUT % 3` 的棒球局数表示 |
| P S | 实际投球数 P 与实际好球投球数 STR 的组合 |

RA9 使用九局口径，表示投手每九局的失分；ERA 只使用自责分。投手犯规 BK、故意四坏球 IBB 和裁判判罚不会虚增普通投球数。PO 是完成出局的守备球员次数；PICK 是投手的牵制尝试次数。

## 年度累计方式

累计统计不平均逐场 AVG、ERA 或 OPS。系统会先筛选指定年份、指定运动的已结束比赛，回放每场比赛，累加原始统计，再用累计后的分子和分母重新计算比率。棒球与慢投垒球分别汇总，避免不同规则的比赛混入同一累计值。

本局打击数据也使用当前回放日志派生，只取当前局且已经结束的打席，因此不会写回或污染球员生涯统计。

## 导出结构

每次 Excel 导出都通过相同的数据通路生成：统计分类定义字段，工作簿生成器创建 XML 工作表，下载模块保存文件。比赛导出包含总览及客队、主队的打击、守备、投球分类表；投球表只列出实际有投球记录的球员。

逐打席导出会保留时间、局数、攻守、投手、打者、结果、跑者动作、得分、出局、失误、牵制垒包和其他已记录事实，便于赛后复核。

## JSON 备份与导入

JSON 备份保存已结束比赛、所需球员、比赛事件、阵容、工作人员和开始结束时间，不保存一份独立的“最终统计快照”。导入后重新回放事件计算统计，避免备份内的旧统计数字覆盖计算结果。

导入流程依次执行：

1. 检查 JSON 格式、大小、比赛状态、阵容和事件类型。
2. 用规范化的开始时间与结束时间组合识别重复比赛。
3. 用规范化姓名匹配球员；缺失球员加入注册表，已删除的匹配球员恢复。
4. 重映射球员 ID，验证阵容不重复，回放整场比赛并检查统计值。
5. 全部成功后一次性加入本地数据库；任一项失败则不写入部分结果。

## 数据准确性的边界

软件保证已录入事件在同一规则下可重复计算，但不会替代记录者对模糊场景的官方裁决。特别是复杂的申诉、未被录入的独立守备失误、非标准局数、特殊竞赛条例或无法从跑垒事实唯一确定的判罚，需要记录者先把事实录入正确，或在赛后按官方规则复核。
